PATCH #2 — dispatcher "Unknown command" gate (CLI enabler)
================================================================
Problem found: the shipped bundle is the nvflash_eng engine behind a
restricted "nvuflash" FIELD-UPDATE front-end. Its CLI dispatcher
(FUN_0092406e) routes:
    help        -> usage
    licenseinfo -> license text
    dump        -> show embedded PLDM package info
    version     -> show adapter firmware versions
    <any other RECOGNIZED invocation> -> *** UPDATE embedded firmware ***
The update is the DEFAULT action. But the dispatcher first calls
param_1[1]->vtable[0x18]() ; if it returns nonzero it prints
"Unknown command" + usage and exits (return 5). That method is a plain
getter:
    FUN_0057c719:  movzbl 0x60(%rdi),%eax ; ret   (returns parser byte 0x60)
Byte 0x60 is the parser's "unrecognized / no primary command" flag, which
is set for a bare run and for any token not in the (runtime-built) command
table — so the embedded UPDATE path was unreachable from a plain CLI call.
(That is why bare run and --autoupdate both printed "Unknown command".)

Patch: force the getter to always return 0 ("recognized").
File offset : 0x17c719   (vaddr 0x57c719)
Original 5b : 0f b6 47 60 c3   (movzbl 0x60(rdi),eax ; ret)
Patched  5b : 31 c0 66 90 c3   (xor eax,eax ; nop ; ret)  -> always 0

Effect: --help/--dump/--version/--licenseinfo still work (checked first);
every other invocation (including a bare `sudo ./nvflash_unlocked`) now
falls through to the DEFAULT embedded-firmware UPDATE path.

NOT touched (brick protection stays active): Board-ID/model match, ERoT
